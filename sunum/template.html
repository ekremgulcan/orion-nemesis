01 // SKILL NEDİR

Bir Agent Skill, Tekrar Kullanılabilir Uzmanlıktır

  • Ajanın belirli bir görev türünde tekrar tekrar ihtiyaç duyacağı talimatları, referans dosyalarını ve çalışan script'leri bir araya getiren, ihtiyaç anında yüklenen bir bilgi paketidir.
  • Genel sohbet ya da tek seferlik işlerde değil; tekrarlanan, alan bilgisi gerektiren görevlerde devreye girer — bir ekran migrasyonu, bir test süreci, bir veritabanı keşfi gibi.
  • Amaç: ajanın her seferinde aynı bilgiyi sıfırdan yeniden keşfetmesini önlemek; tutarlı ve tekrarlanabilir sonuç almak.
01 // İDEAL YAPISI

Az ama Doğru Bilgi: Progressive Disclosure

  • description alanı en kritik alandır — ajan skill'i ne zaman çağıracağını sadece bu açıklamadan anlar; somut tetikleyici ifadeler içermelidir.
  • SKILL.md kısa ve öz tutulur (ilk yüklenen katman); detaylı referanslar references/e, çalışan kod scripts/e ayrılır.
  • Derinlemesine bilgiye sadece gerektiğinde inilir — ajan referans dosyalarını ihtiyaç anında okur, hepsini önceden yüklemez.
  • Soyut kural değil, kanıtlanmış çalışan örnekler içerir — bu süreçte: referans test script'leri, DOM keşif notları.

02 // MOCK ORION

Gerçek Platformu Taklit Eden İzole Ortam

  • Backend: Spring Boot 2.7.18 (javax.persistence / javax.servlet), Java 17
  • Legacy arayüz: ZK7 (.zul + ViewModel)
  • Veritabanı: MSSQL, Docker container, Flyway migration ile seed veri
  • Yeni arayüz: React + Vite (nemesis-frontend), aynı REST API'yi kullanır
  • Amaç: gerçek Orion v3 Nemesis platformunu bire bir yansıtan, üzerinde güvenle çalışılabilecek bağımsız bir ortam kurmak.

03 // DB-EXPLORER

Herhangi Bir SQL Veritabanını Anlaşılır Kılan Subagent

  • Read-only: sadece keşif yapar, hiçbir veriyi değiştirmez.
  • Bağlantı bilgilerini kendi bulur; şemayı, ilişkileri, satır sayılarını çıkarır.
  • Kod tabanıyla (entity / repository / ekran) eşleştirip "hangi tablo hangi ekrana karşılık geliyor" sorusuna yanıt verir.
  • Çıktı: veritabanını hiç görmemiş biri için bile anlaşılır, sade bir özet.
04 // EKRAN MİGRASYONU

ZK7'den React'e: Ekran Başına Güvenli Dönüşüm

  • Mevcut ViewModel / Service'ten iş mantığı çıkarılır.
  • Yeni bir REST + DTO katmanı eklenir — eski ZK ekranlarına ve veritabanı şemasına dokunulmaz.
  • Orion dark-theme, 3 kolonlu tasarım sistemiyle React sayfası oluşturulur.
  • Sonuç: planlanan tüm ekranlar tek tek React'e taşındı — iki versiyon da yan yana çalışır durumda.

05 // TEST OTOMASYONU

Uçtan Uca Doğrulama: Tarayıcı + Veritabanı

  • Puppeteer ile hem ZK7 hem React ekranları sürülür — id'lere değil, görünür metne / DOM sırasına güvenilir.
  • Sonuç, MSSQL'de doğrudan sqlcmd sorgusuyla doğrulanır.
  • Çapraz ekran kontrolü: bir ekranda oluşturulan kayıt, ilgili onay/görünüm ekranında da doğrulanır.
  • Script'ler kalıcı: aynı senaryo tekrar istendiğinde yeniden yazılmaz, doğrudan çalıştırılır — zamanla büyüyen bir regresyon suite'i.
05 // ÖRNEK ÇIKTI

Her Çalıştırmadan Kalıcı Bir HTML Rapor

  • Kritik adımların ekran görüntüsü
  • Çalıştırılan SQL sorgusu + dönen satırlar
  • PASS/FAIL özeti ve toplam süre
  • Orion'un kendi tema diliyle üretilir
05 // HATA DURUMUNDA

Sadece FAIL Değil: Nerede, Neden, Nasıl Düzelir

  • Console / network hataları otomatik yakalanır (yakalanmamış JS hataları, 4xx/5xx yanıtlar)
  • Başarısız her adımda "Neden başarısız oldu? / Potansiyel çözüm" kutusu gösterilir
  • Bu bir başlangıç noktasıdır — nihai teşhis değil, ajan hala kendi değerlendirmesini yapar
